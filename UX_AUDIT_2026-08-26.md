# UX Audit — Rother Dashboard vs. Monitoring-Core Needs
**Date:** 2026-08-26 · **Scope:** information architecture of the 28-feature
dashboard; comparison to GMBE (Google Maps Business Everywhere).
**Inputs:** code inventory (`src/lib/features.tsx`), partial screenshot review
(landing / hub navigator / Insights section / KPIs page).

---

## 1. What the dashboard IS today

28 features in 4 hubs:

- **Insights (6):** KPIs, Run Health, Rating Distribution, New Reviews per
  Branch, Run Comparison, Run History
- **Reputation (8):** All Reviews, Reviews over Time, Review Lengths,
  Word Cloud, Language, Recency Heatmap, Top Reviewers, Alerts
- **Competitors (10):** Branches & Competitors, Branch Comparison,
  Leaderboard, Radar Comparison, Growth Rate, Correlation,
  Competitive Health, Discover, Geo grid, Rating Dist Compare
- **Tools (4):** Config, Run Logs, Export, Scrape Schedule

The shell itself is well-executed (landing → 4-hub navigator → section →
feature, consistent Bali design system, lazily loaded, Cmd+K palette).
The question is the FEATURE SET, not the chrome.

## 2. Redundancies in the feature inventory

| Cluster | Surfaces | Assessment |
|---|---|---|
| **Run management** | Run Health + Run History + Run Comparison (Insights) + Run Logs (Tools) | 4 ways to answer "how did scrapes go" — should be ONE "Runs" feature with tabs (Health / History / Compare / Logs) |
| **Time views** | Reviews over Time vs Review Recency Heatmap | Same data, two shapes; heatmap is a viz variant of the timeline. Merge into one with a view toggle |
| **Comparison** | Branch Comparison + Competitor Comparison (radar) + Leaderboard + Rating Dist Compare | 4 comparisons. Leaderboard is the natural home (sortable table); radar/comparison a supplemental view. Not harmful, but the hub has 10 cards for this |
| **Discovery/intelligence** | Discover (scan) + Competitive Health (OSM fusion) + Correlation + Geo grid | Overlapping territory: competitive-health already fuses discovery + correlation. Discover = the "add" action; geo-grid = the map. Reasonable, but dense |
| **Alerts** | Alerts (Reputation) vs Run Health (Insights) | Different (review-data alerts vs scrape errors) — OK |

## 3. Comparison to GMBE (Google Maps Business Everywhere)

| | GMBE | Rother |
|---|---|---|
| Purpose | One-shot business audit | Continuous monitoring + change detection |
| Core flow | Paste link → scorecard on ONE screen | Onboarding → scrape → navigate hubs |
| Answer density | Everything on first screen | Value distributed across ~7–8 features |
| Alerts/deltas | None | Core strength (ever-seen deltas, variance-proofed) |
| Comparison | Limited/raw | Leaderboard, radar, rating dist, geo |
| Setup cost | Zero | Onboarding + first scrape |

**They are different products.** GMBE answers "how is this place doing,
right now" on a single screen. Rother answers "what changed, and how do we
compare over time" — which inherently needs more structure. You should not
copy GMBE's surface area; you should steal its **answer-first density**.

## 4. Verdict — are 28 features too many?

**For daily monitoring: yes. For a monitoring platform: no, but the
hierarchy is wrong.** The core daily-need set is ~7:

- KPIs, Rating Distribution (health at a glance)
- All Reviews, Alerts (the v2 flow also shows new/recent)
- Leaderboard or Branches & Competitors (comparison at a glance)
- Config, Scrape Schedule (ops)

Everything else (run quartet, time-heatmap duplicate, correlation,
word cloud, language, lengths, growth, recency variants) is analytics
garnish. Neither GMBE nor a small-business owner opens 28 cards to learn
"did anything new happen".

## 5. Recommendations (tiered, low-risk first)

**Tier 1 — re-hierarchy only (no feature removal):**
- After a run / on re-open, land on a **"Today" composite**: alerts + new
  reviews + rating snapshot + partial-window honesty, one screen. The
  4-hub navigator moves one level deeper or becomes a slide-over rail.
  (GMBE's answer-first lesson.)

**Tier 2 — collapse duos:**
- Merge the run-management quartet into **one "Runs" feature** with tabs
  (Health / History / Compare / Logs).
- Merge Reviews over Time + Recency Heatmap into one with a view toggle.
  28 → ~24 cards with zero capability loss.

**Tier 3 — guided spotlight (optional):**
- Default-pin the 7 core features at hub top; demote the rest behind a
  "More analytics" section per hub.

**Do NOT:** remove features outright (each is real and tested, e2e-covered);
do NOT copy GMBE's one-screen model (monitoring ≠ one-shot audit).

## 6. Status

Assessment complete. Tier 1 re-hierarchy is the highest-value, lowest-risk
next step if desired; Tiers 2–3 are optional consolidations. No code
changed in this audit.
